# 写真をもとにしたプロフィール用3Dシーンの制作と調整手順

写真や参考画像を見ながら、机と小物を Three.js の図形で組み立て、Webページで視点や配色を変えられるようにする手順です。はんなりdev の `/profile/` を例に、別の写真を使う場合の作業順と、この実装を調整する際の編集先をまとめています。

この実装では [日なたの参考画像](../../../sys/src/assets/images/orange.png)、[薄紫の参考画像](../../../sys/src/assets/images/purple.png)、[画角の参考画像](../../../sys/src/assets/images/green.png) から、構図、色、各物体の大きさと重なりを読み取りました。正面から見えない奥行きや裏面は、別角度で見ても自然になるように推定して組み立てます。窓の外は別に用意した風景画像を平面へ貼っています。

## 1. 作業を始める

コマンドはリポジトリ直下から `sys` に移動して実行します。Node.js は `package.json` の条件を満たす版を使います。この手順の確認時は Node.js 22.23.5 で、静止画の生成スクリプトから TypeScript のシーン定義を直接読み込んでいます。

```powershell
Set-Location sys
npm run dev -- --port 4321
```

依存関係をまだ入れていない作業環境では、先に `npm ci` を実行します。`http://localhost:4321/profile/` を開き、代表者名の下のデスクまでスクロールします。現行の初期表示は **若葉・昼・標準の右16度** です。開発時の画角ボタンを使うと、複数の角度で同じ変更を比べられます。

| 変更したいもの | 主な編集先 |
| --- | --- |
| 机、小物、部屋、窓、ライト、カメラ | [profile-desk.ts](../../../sys/src/profile-desk.ts) |
| プリセットの角度、初期画角、ドラッグの上限 | [profile-desk-views.ts](../../../sys/src/profile-desk-views.ts) |
| 5色の配色、色見本、初期色、初期の昼夜 | [profile-desk-themes.ts](../../../sys/src/profile-desk-themes.ts) |
| 鳥の影と流れ星の形、位置、速度、間隔 | [profile-desk-window.ts](../../../sys/src/profile-desk-window.ts) |
| モニターに打ち込むコードとカーソル | [profile-desk-editor.ts](../../../sys/src/profile-desk-editor.ts) |
| スイッチ、ドラッグ、描画の開始と停止、静止画への切り替え | [ProfileDesk.astro](../../../sys/src/components/ProfileDesk.astro) |

## 2. 写真から構図と寸法を決める

1. 参考画像を表示して、机の左右端と前後端、モニターの外枠、左右のスピーカー、壁の境界を拾います。最初はメモや簡単な線で十分です。細部の色や質感は後で合わせます。
2. 基準寸法を一つ決めます。このシーンでは天板幅を `10.6` とし、モニター外枠の幅を `3.68` にしています。たとえば正面に近い写真でモニターが天板幅の約35%なら、`10.6 × 0.35 ≈ 3.7` を初期値にできます。奥行きの異なる物体や斜めに写る物体では、写真上のピクセル比を出発点とし、3D上で調整します。
3. 机の中央と天板の高さを原点にします。このシーンの座標は `[X, Y, Z]` で、`X` は左右、`Y` は上、`Z` は奥から手前に向かって増えます。天板の上面は `Y = 0`、床は `Y = -1.64`、背面の壁は `Z = -1.57` です。
4. 壁、床、天板、モニター、スピーカーを仮の箱と平面で置きます。正面で幅と高さを合わせ、斜めから見て物体同士の前後関係を合わせます。机の奥行きや物体の厚みは、正面の写真だけで決まりにくいため、別の写真があれば優先して参照します。
5. 標準画角とスマートフォン相当の幅で、机が切れないこと、余白が自然なことを確認します。ここで外形を揃えてから、ランプ、鉢植え、キーボード、カップ、時計の順に足すと、元画像とのずれが見つけやすくなります。

配置にはシーン内の長さを使います。箱は中心で配置するため、厚さ `0.22` の天板を `Y = -0.11` に置くと上面が `Y = 0` になります。同じ考え方で、厚さ `0.1` のキーボード本体は局所座標の `Y = 0.05` に置きます。

## 3. オブジェクトを組み立てて調整する

下の数値は現行シーンの基準です。配置は [createDeskScene](../../../sys/src/profile-desk.ts) 内にあります。別の画像で使い回すときは、まず各部品の中心位置と寸法を置き換えます。

| オブジェクト | 現行の作り方と調整箇所 |
| --- | --- |
| 部屋と巾木 | `surface()` と `PlaneGeometry` で床と背面・左右の壁を作る。床は `floorY`、背面は `wallZ`、左壁は `cornerX` を基準にする。床を上下させる場合は、巾木の高さも合わせる。 |
| 天板 | 上段は寸法 `[10.6, 0.22, 3.1]`、中心 `[0, -0.11, 0]`。下段は `[10.2, 0.28, 2.75]`、中心 `[0, -0.35, 0]`。幅や奥行きを変えるときは上下段を揃え、脚なしでも成立する表示範囲か確認する。 |
| モニター | 台座、支柱、外枠、黒い画面、表示灯を箱で重ねる。外枠は `[3.68, 2.19, 0.22]`、中心は `[0, 1.48, -0.59]`。画面の内側は `deskScreen` で管理する。 |
| スピーカー | 左右をループで作り、各 `Group` の基準位置は `[±3.86, 0, -0.57]`、回転は `-side * 0.18` rad。筐体は丸い角の箱、前面に円筒と扁平な球を重ねる。 |
| キーボード | `keyboard` グループは `[-0.02, 0, 0.93]` に置く。本体は箱、42個のキーは `InstancedMesh` で14列×3行。間隔や段数を変えるときは、スペースキーと本体の寸法も調整する。 |
| マウス | `[1.76, 0.085, 0.98]` の球を `scale.set(0.22, 0.12, 0.33)` で扁平にする。位置と底面の接地を一緒に確認する。 |
| カップとコーヒー | `cup` は `[-2.38, 0.22, 0.64]`。円筒の胴体と液面、トーラスの縁と取っ手を重ねる。取っ手には別の絶対座標があるため、移動時に一緒にずらす。 |
| ノートと紙 | 机の左手前に薄い箱を2枚重ね、それぞれ `rotation.y` を変える。素材の厚みを調整したら、紙が浮いたり下の面に埋まったりしていないかを斜めから確認する。 |
| デスクライト | 円筒の台、`tube()` の支柱、`shade` グループの傘と電球で構成する。傘の中心は `[2.38, 1.69, 0.36]`。位置を変えたら `deskLamp.x`・`z` も調整して、夜に照らす場所と合わせる。 |
| 植木鉢 | 円筒の鉢と土、引き伸ばした球の葉3枚を組み合わせる。葉ごとに高さと `rotation.z` を変える。鉢を移動する場合は葉と土も追従させる。 |
| 時計と壁の絵 | 時計は `clock` グループで、基準位置は `[2.57, 2.92, wallZ + 0.065]`。壁の絵は左上に箱と小さな円筒を重ねている。背面の壁を動かす場合は `wallZ` からのわずかな手前方向の距離を保つ。 |
| 右壁の窓 | `deskWindow` と `rightWall()` で開口部を作り、枠、縦桟、金具、風景を重ねる。位置の変更は光の形にも影響するため、後述の「窓光と座標」も確認する。 |

### まとめて移動できる形にする

箱や球の寸法は `box()` などに渡し、全体の置き場所は `Group.position` で変えます。たとえばスピーカーを左右にそれぞれ `0.24` 広げるなら、`speaker.position.set(side * 3.86, 0, -0.57)` の `3.86` を `4.10` に変更します。筐体とユニットは同じグループ内なので一緒に動きます。変更後は標準と左右の画角で、天板の外に出ていないか、鉢やランプに重なっていないか確認します。

モニターは画面本体、静止画用の `editorPoster`、ライブ用の CanvasTexture 平面が別に定義されています。モニター全体の位置を変えるときは、土台・支柱・外枠・表示灯・`editorPoster` に加え、`deskScreen` と `createProfileDesk()` 内の画面平面も追従させます。X方向へ移す場合は、`projectScreen()` の中心Xにも同じ値を渡します。画面の位置や寸法が変わったら、静止画と投影座標を再生成します。

小物を増やす場合は、`createDeskScene()` の小物の定義付近に次のように追加できます。例は天板左手前の小物です。既存のカップやノートと交差する場合はX・Zを移してから寸法を決めます。

```ts
outline(box(scene, [0.52, 0.06, 0.36], detail, [-1.6, 0.03, 0.86], 0.02));
```

`box()` は角を丸めた直方体、`cylinder()` は円筒、`tube()` は点列を滑らかにつないだ管です。`mesh()` では影を落とし、影を受ける設定を有効にします。`outline()` は膨らませた裏面を描くため、輪郭を付ける対象を主要な物体に絞ると読みやすくなります。既存の不透明な `MeshToonMaterial` や `MeshBasicMaterial` を使うと、静止画生成側でも扱いやすくなります。別の材質を導入する場合は、生成スクリプト側でその材質をどう描くかも決めます。

## 4. カメラと配色を合わせる

### カメラ

[画角の定義](../../../sys/src/profile-desk-views.ts) は左上 `-25°`、正面 `0°`、標準 `16°`、右上 `25°` です。横ドラッグはライブ描画で `±35°` の範囲に制限します。静止画表示中はドラッグ位置に最も近いプリセットを使います。

`profile-desk.ts` の `aim(angle)` では平行投影の `OrthographicCamera` を使います。`viewWidth` を大きくすると構図に余白が増えます。`camera.position` のYを上げると天板がより見下ろしになるため、`lookAt()` の着地点と合わせて直します。現行の `aim()` は、正面と斜めで撮影範囲や高さを補間します。正面だけを見て調整せず、標準、左右、ドラッグの上限でも確認してください。

別の写真で机が大きく切り取られている場合は、撮影画像のクロップとWeb上の構図を先に決めます。現行の表示枠は `16 / 9` です。枠の比率を変える場合は、ライブのカメラと静止画の出力寸法、それに `object-fit: cover` での重ね合わせを一緒に確認します。

### 配色と昼夜

`deskThemes` で一つのテーマに対する `desk`、`wall`、`side`、`floor`、`accent`、`detail`、`leaf`、`trim`、`ink` などを管理しています。`swatch` は選択ボタンの丸い色見本、`background` は画像の背景色、`light` は昼に窓から差す光の色です。たとえば机を淡くする際は、まず広い面の `desk`、`wall`、`floor` を調整し、時計やランプなど限られた面の `accent` や `detail` で色を立たせます。右壁の材質は床の色を参照します。

材質には `MeshToonMaterial` を使い、少ない明度段階で面の明るさを描きます。木の面は `matte(color, 1)` の第2引数で木目を加えます。粒子や木目を調整する場合は、ライブ描画の `paintTexture` と、静止画生成から呼ぶ `deskPaintMultiplier()` を揃えます。

`setLighting()` で半球光を昼 `2.75`・夜 `1.48`、指向性ライトを昼 `2.15`・夜 `0.46` に切り替えます。夜は青みのある光を弱くし、デスクライトの電球を発光させて天板に暖色の光を残します。ライトの光が広すぎる場合は `deskLamp.radius` を調整します。床への漏れや高さによる減衰を変更する場合は、ライブ描画側の `lampMask` と静止画用の `deskLampFalloff()` を揃えます。

## 5. 窓の外と室内へ落ちる光を作る

### 窓と風景の作り方

現行の窓は、右壁の `X = 10.08` 上に幅 `3.8`（Z方向）、高さ `2.68` の開口を設けています。周囲の壁は開口を避けて平面を組み、枠と縦桟の後ろに風景の平面を置きます。風景用の画像には部屋や窓枠を描き込まず、外だけを用意すると、形状側の枠と合わせやすくなります。

昼の [田舎町の風景](../../../sys/src/assets/images/profile-desk-countryside.webp) は、瓦屋根、家並み、路地、遠景の山を描いた画像です。参考画像から新しい外景を用意する場合は、窓越しに見たい場所、見下ろす高さ、必要な空の量、画風を決めてから画像を用意します。先行作業の画像生成プロンプトは [dev-plan-004](../../../doc/dev-plan/dev-plan-004-profile-3d.md#田舎町の生成プロンプト) にあります。夜景は生成スクリプトが昼景を暗く青く調整し、空のグラデーション、月、星を重ねて `profile-desk-countryside-night.webp` を出力します。夜景を変えるときは、生成された画像を直接直す代わりに、昼景の入力画像またはスクリプトの `skyLayer` と色補正を調整します。

### 窓光と座標

指向性ライトを `deskWindow.direction = (11, 5.2, 4.6)` の方向に置きます。壁や机上の点 `P` から光源側へ光線を戻し、右壁の窓のどこを通るかを求めます。

```text
t = (窓の X - P.x) / 光の方向 X
u = (P.z + t × 光の方向 Z - 窓の始点 Z) / 窓の幅
v = (P.y + t × 光の方向 Y - 窓の始点 Y) / 窓の高さ
```

この交点が窓の開口に入ると直接光を強くし、枠と縦桟に当たる部分は弱くします。これで窓の見た目とは別に、壁や天板に窓枠の形が現れます。標準画角では窓そのものは画角外にあり、壁や机に落ちる光で演出が見えます。窓を光の方向に沿って移すと、光線の通り道を保ちながら窓の見える位置を調整できます。窓の幅や光の方向を変えたときは、ライブ側の窓のマスクと静止画側の `windowMask()` を確認し、光の投影マップも再生成します。

3Dの座標、ディスプレイ上の座標、窓のテクスチャ座標は別です。窓のアニメーション用の Canvas では、`x = u × 320`、`y = (1 - v) × 224` で描画します。窓上でXを増やすと、背面の壁に投影された光は画面の左へ動きます。流れ星を右から左へ流すときは、窓用 Canvas のXを増やします。

## 6. アニメーションを調整する

### 鳥の影

`profile-desk-window.ts` の `paintFlock()` で群れ全体の移動を、`paintBird()` で各鳥の形を作ります。現行は3羽が約10.4秒で窓座標を横断し、群れの描画が終わると3秒待って次の群れを開始します。画面上で見える時間は、窓光が壁や机を照らす範囲にも依存します。

| 調整 | 編集する値と見方 |
| --- | --- |
| 通る高さ | `paintFlock()` のY式にある `0.10` を小さくすると、窓用 Canvas 上で高くなる。たとえば `0.06` にすると、窓上の基準位置は約9px上がる。実画面では光の投影を見て判断する。 |
| 鳥の距離と隊形 | `birdFlock` の `offsetX` と `offsetY` を変える。個別に開始時刻をずらすより、共通の位置に小さな相対座標を足すと群れに見える。 |
| 揺らぎ | 群れ全体の `Math.sin(elapsed / 820) * 2.2` と、鳥ごとの `drift` を調整する。振幅を上げると揺れ幅が増え、除数を小さくすると揺れが速くなる。 |
| 形と横幅 | `paintBird()` のパスでくちばし、翼、尾を作る。横幅だけを短くするならパスのX座標を寄せる。翼のY座標は `farWing` と `nearWing`、羽ばたきの位相は `phase` で調整する。 |
| 影の濃度と見えやすさ | `brush.globalAlpha` は現行 `0.9`。小さくして消える場合は `birdStroke` を確認する。線幅は `birdStroke / size` として、図形を縮めても輪郭の最低限の太さを残す。 |
| 速さと頻度 | `birdDuration` は1回の群れの移動時間。`play()` の昼の待ち時間は次の群れまでの間隔。1羽の速さを保って頻度だけを変えるには待ち時間を直す。 |

### 夜の流れ星

`meteorPasses` は各星の開始時刻、出発点、終点の高さ、相対的な大きさを保持します。現行は4つで、基準の開始時刻は `0 / 1300 / 2850 / 4250` ms です。移動時間は `meteorTravel = 450` ms、夜の次の一巡までの待ち時間は `9500` ms です。

- **速さ**は `meteorTravel` で調整します。同じ軌道を約2倍速く通すなら値を半分にします。軌道上の進み方は `0.35 × t + 0.65 × smoothstep(t)` で、序盤と終盤をゆるやかにし、中盤で加速します。
- **大きさ**は `meteor.size`、光の芯の `radius`、尾の長さの下限と上限で調整します。芯を小さくすると、窓用の画像から投影先へサンプリングしたときに光が消えやすくなるため、まず尾を短くし、芯は明るさと一緒に確認します。
- **流れる範囲**は `createMeteorPaths()` が一巡ごとに決めます。窓光の中央付近から画角ごとの左側の上限までを帯に分け、各帯で少しばらつかせます。毎フレーム乱数を引くと途中で軌道が飛ぶため、開始時に決めた終点を使い続けます。
- **消え方**は `meteorFadeStart` を変えます。現行は進行時間の60%を過ぎたところから、芯と尾を一緒に薄くし、動きながら消えます。窓枠や家具の影に入ると途中で見えなくなる場合は、`meteorLeftEdge` と `endY` を投影先に合わせます。

### モニターのコード

`profile-desk-editor.ts` の `lines` を差し替えると表示コードが変わります。現行の作画面は `480 × 268`、本文は10pxの等幅書体です。文字の表示は `paint(time)` で進み、`ProfileDesk.astro` のタイマーとアニメーション側で80ms刻みを使います。速度を変える場合は、タイマーの間隔、`codeTime` の増分、エディターの時間計算の関係を確認します。開発画面の「コードを一時停止」は、窓の外のアニメーションとは独立しています。

ライブではコード用の Canvas をモニターの平面に貼ります。WebGL なしでは静止画へ Canvas を重ね、`profile-desk-screen.json` の左上、右上、左下の座標からCSSの `matrix()` を求めます。見た目を変えるだけなら `lines` などを調整し、モニターの形や位置まで変えたら静止画と投影座標を再生成します。

### 小物本体を動かす場合

時計の針やランプの傘などを動かす場合は、対象を `Group` や `Mesh` の参照として保持し、アニメーションの経過時間に応じて `position` や `rotation` を更新してから描画します。窓の演出は影の濃淡を変える方式ですが、小物本体を動かすと他の面に落ちる影の形も変わります。現行のWebGL描画では影のマップを毎回更新していないため、影を落とす小物を動かす場合は、位置を変えたフレームで `renderer.shadowMap.needsUpdate = true` にします。WebGL なしで使う静止画には、止めて見せたい姿勢を採用します。

## 7. 静止画と投影データを再生成する

ライブの Three.js と、WebGL が使えない場合の静止画は、同じ `createDeskScene()` から作ります。静止画の上でも窓光とモニターのアニメーションはCanvasで動きます。窓光のPNGは投影マップとして使います。赤と緑に記録したUVでアニメーションの窓上の位置を参照し、青に記録した光の強さで室内に現れる濃淡を制御します。

```powershell
# リポジトリ直下から実行する
Set-Location sys
node scripts/render-profile-desk.mjs
npm run check
npm run build
npm run preview -- --host 127.0.0.1 --port 4322
```

生成スクリプトは以下を更新します。

| 出力 | 内容 |
| --- | --- |
| `src/assets/images/profile-desk-*.webp` | 5色×昼夜×4画角のデスク静止画40枚。描画は1440×810、書き出しは幅1120px。右上の画角は名前に `-right` が付かず、夜は `-night` が付く。 |
| `src/assets/images/profile-desk-countryside-night.webp` | 昼景と空の素材から合成する窓の外の夜景。 |
| `src/assets/images/profile-window-light-*.png` | 4画角の光の投影マップ。幅720pxで、位置がずれないよう最近傍で縮小する。 |
| `src/profile-desk-screen.json` | 4画角のモニター画面の投影座標。 |

形状、カメラ、材質、照明、外景を変えたときは生成スクリプトを先に実行します。鳥や流れ星のタイミング、ルート、形など、既存の窓UV上で描く内容だけを変えた場合は、通常は静止画や投影マップの再生成は不要です。配色を追加した場合は、生成して全画角・昼夜の画像を揃えてからビルドします。部屋の面を縮めたり視野を広げたりして `Room does not cover the camera view` が出た場合は、全画素を壁と床で覆えるように面の寸法と角度を見直します。

## 8. 変更後の確認と切り分け

1. **初期表示**を確認します。若葉、昼、標準から始まり、色のインジケーターと昼夜の切り替えが操作できることを見ます。
2. **構図**を確認します。正面、標準、左上、右上を切り替え、机が切れないこと、小物の接地、窓や時計の重なりを確認します。スマートフォン相当の幅でも確認します。
3. **動き**を確認します。昼は鳥の影が窓光の部分だけに現れ、夜は4つの流れ星が右から左へ流れて徐々に消えることを見ます。暗い場所や明るい植物の前で見えにくい場合は、まず窓上の座標が投影可能か確認します。
4. **描画方式**を切り分けます。開発者ツールの要素パネルで `[data-profile-desk]` に `data-live` が付いていれば WebGL で描画しています。付いていなければ静止画への切り替え、読み込み待ち、または初期化失敗を確認します。開発時のコンソールには初期化失敗の理由が出ます。
5. **静止画との位置合わせ**を確認します。ローカル開発で開発者ツールのネットワークリクエストをブロックできる場合は、`*/src/profile-desk.ts*` を対象にしてページを再読み込みすると、静止画表示を試せます。モニター内のコードが画面枠に収まるか、窓光のマスクと影の位置が一致するかを確認し、確認後にブロックを解除します。ずれがある場合は、カメラと生成済みJSON・PNGの組み合わせ、画像と重ねるCanvasのアスペクト比、`object-fit: cover` を順に確認します。
6. **停止条件**を確認します。アニメーションはシーンが画面外、タブが非表示、または「動きを減らす」設定のときに停止します。見えない場面を調べる前に、シーンを表示領域へ入れてアクティブなタブで確認します。「動きを減らす」設定ではモニターに完成したコードを表示します。
7. **本番プレビュー**を確認します。`http://127.0.0.1:4322/profile/` で色と昼夜の操作を確認します。配色名の開発ボタン、画角ボタン、コード一時停止ボタンは開発時のみ出ます。本番でもデスクをドラッグして回転できます。

### 数値を変えたのに見た目が変わらないとき

編集したソースと、ブラウザーが表示している環境を確認します。開発は `4321`、上記の本番プレビューは `4322` です。本番プレビューには `npm run build` 後の出力が反映されます。ライブだけ新しく静止画だけ古い場合は生成スクリプトを実行します。鳥や星が小さすぎる場合は、まず標準画角で光の範囲内の位置に一時的に寄せて見え方を比べ、影の輪郭幅または星の芯を調整します。
