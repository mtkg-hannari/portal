## 1. 結論

**アピールポイントになります。掲載を推奨します。** 現在のサイトの最大の弱みは「実績・信頼の根拠が弱い」こと（マーケティング計画 1.2）です。次の 3 つは、この弱みを直接補えます。

| 材料 | 効果 | 評価 |
| --- | --- | --- |
| IT 業界でのキャリア 20 年以上 | 経験の厚み。「小さな会社でも任せて大丈夫か」という不安に答える | 強い（数字で示せる） |
| IPA 高度試験の合格（プロジェクトマネージャ／ネットワークスペシャリスト／データベーススペシャリスト） | 第三者が認めた専門性。**3 区分の合格は希少**で、PM（進行管理）・基盤（NW）・データ（DB）を一人でカバーできるという具体的な強みになる | 強い（特に BtoB・企業の担当者に効く） |
| ココナラでの評価・実績 | 実際の取引に基づく**第三者の評価**。顧客名を出せない現状でも信頼を示せる。評価 5.0、販売実績 92 件、プロ認定 | 強い |

### なぜ効くか

- 現サイトは「設計力」「要件定義を中心に置く」「作って終わりにしない」を打ち出している。**PM と DB は、その主張を裏づける資格**として相性が良い（要件定義・計画・データ設計）。NW は、業務システムや Web サービスの基盤・運用の話に説得力を足す。
- 個別の導入事例や顧客名を公開できなくても、「資格」「年数」「評価」は**顧客情報に触れずに**出せる信頼材料になる。
- 主ターゲット（関西圏の中小企業・IT 部門が小さい企業）は、発注先の技術力を自分で判断しにくい。**資格と年数は判断の手がかり**になる。

### 注意点（正確さ・信用）

1. **表記は正確に。** IPA の情報処理技術者試験は「合格」が正式な表現です。「〜試験 合格」と書き、必要なら合格年度も添える。「資格保有」と書く場合も、実態（合格・登録有無）と一致させる。誇大表現は逆効果（マーケティング計画 4.2 の方針とも一致）。
2. **古さへの配慮。** 合格年度が古い場合は、年度を出すより「20 年以上のキャリア」と合わせて、現在も実務で使っていることを示す（直近の案件分野・Journal 記事など）。
3. **ココナラの数字は事実どおりに、時点を添えて。** 評価・販売実績は変動するため、「（2026年11月時点）」を必ず添える。評価文の転載・スクリーンショットの掲載は行わない（ココナラの規約と購入者への配慮のため）。画像は自前のイラストを使う。
4. **個人情報の扱い。** 実名・写真・所在地をどこまで出すかは未決定（マーケティング計画 5 #5）。資格や評価は「誰の実績か」が分かって初めて効くため、**代表者の公開範囲とセットで決める**。
5. **「3 資格 = 何でもできる」とは書かない。** 資格が示すのは知識と問題解決力。サイトの主張（設計・要件定義）に結びつけて書くと信頼されやすい。
6. **証書の画像は公開しない。** 合格証書は、氏名・生年月日・証書番号などの個人情報を含みうるため、Web に載せない（2026-11-24 に削除済み。加工元の画像はローカルの `private/` で管理し、git・公開の対象外）。

## 6. リスクと対応

| リスク | 対応 |
| --- | --- |
| 資格・年数の表記が実態とずれ、信用を失う | フェーズ0で事実を確定し、フェーズ4で二重チェックする |
| ココナラの数字が古くなり、実態と異なる表示になる | 時点を併記し、四半期ごとに更新する運用にする |
| 証書の画像や個人情報が公開される | 証書画像は `public/` に置かない（削除済み）。`private/` は git・公開の対象外 |
| 個人名・写真の公開に抵抗がある | 判断事項 #1 で非公開案も用意（資格・年数・評価は匿名でも出せる） |
| 「資格を並べただけ」に見えて響かない | 各資格を「何ができるか」に言い換え、Philosophy（設計力）につなげる |
| 掲載により既存の文言（「顧客名は掲載しません」等）と食い違う | フェーズ3で Works の導入文を確認済み（矛盾なし） |
| 問い合わせフォームが送信先未設定のまま公開される | フェーズ4で確認（`FORM_ENDPOINT` / `CONTACT_EMAIL`） |
