# はんなりdev ポータル 開発計画（dev-plan）

作成日: 2026-11-22
対象: `portal/sys`（はんなりdev ランディングページ / Vite + React 19 + TypeScript + Tailwind CSS v4）

> **2026-11-22 追記**: 技術基盤を Vite + React から Astro に移行しました（`dev-plan-002-astro.md`）。本書のフェーズ2（フォント最適化・OGP・sitemap・画像最適化・404）の多くは Astro 版で実施済みです。フェーズ1（フォーム送信先・会社情報など）は未完了のため、引き続き本書で管理します。コード上の場所は `portal/sys`（Astro）です。

## 1. 現状（2026-11-22 時点）

| 項目 | 状態 |
| --- | --- |
| 構成 | 単一ページ LP。Header / Hero / Philosophy / Services / HowWeWork / Works / Journal / Company / InquiryForm / Footer |
| デザイン | **カラー 17「浅葱と砂」× フォント 5「丸ゴシック」で確定**。テーマ／フォント切替バーは画面から撤去済み（定義は `src/config/`・`src/index.css` に残置） |
| ホスティング形態 | 完全静的サイト（`npm run build` → `dist/`）。バックエンドなし |
| お問い合わせフォーム | 実装済みだが、`FORM_ENDPOINT` / `CONTACT_EMAIL` がともに空 → **公開すると「送信先が未設定です」と表示される** |
| コンテンツ | Journal は「テーマ紹介」のみ（記事なし）。Company は会社名・事業内容・問い合わせ方法のみ |
| ビルド確認 | `tsc -b` は通過。`vite build` と実ブラウザでの表示確認は未実施（切替バー撤去後） |
| バージョン管理 | git 未初期化 |

## 2. ゴール

1. 浅葱と砂 × 丸ゴシックの確定デザインで、**問い合わせを受け取れる状態で公開**する。
2. 公開後に更新しやすい（記事追加・会社情報の更新）最小限の運用体制を整える。
3. 軽量・高速・アクセシブルであることを保つ（静的サイトの利点を維持する）。

## 3. 非ゴール（今回やらないこと）

- バックエンド／CMS／会員機能の導入
- 多言語化
- テーマ・フォントのユーザー切替機能の復活（必要になった時点で別途判断）

## 4. フェーズ別計画

### フェーズ0: 確定デザインの検証と整理（目安 0.5〜1日）

切替バー撤去の副作用を確認し、コードベースを確定状態に合わせる。

- [ ] `npm run build` が通ることを確認し、`npm run dev` / `preview` で全セクションを目視確認（デスクトップ・スマホ幅）
- [ ] **アンカー移動のオフセット調整**: 各セクションの `scroll-mt-36` はヘッダー＋切替バーの高さ前提。バー撤去後は余白が過大になるため、実際のヘッダー高さに合わせて見直す（`Philosophy` / `Services` / `HowWeWork` / `Works` / `Journal` / `Company` / `InquiryForm`）
- [ ] 浅葱と砂のコントラスト再確認（本文×地、`--accent` の文字色、ボタン／フォーム、フッター白文字）。WCAG AA 以上
- [ ] 丸ゴシック適用時の字間・行間・見出しの折り返しを確認（`--ls-body` など）
- [ ] 不要コードの整理方針を決める（下記「判断事項」参照）
- [ ] git 初期化、`.gitignore` 確認、初回コミット

### フェーズ1: 公開に必須の設定（目安 0.5〜1日）

- [ ] **フォーム送信先の決定と設定**（`src/config.ts` の `FORM_ENDPOINT` / `CONTACT_EMAIL`）
  - 推奨: Formspree 等の JSON 受け取りエンドポイント。メールアドレスは mailto フォールバックとして併設
  - 送信テスト（正常系・必須未入力・ネットワーク失敗）を実施
- [ ] スパム対策（ハニーポット項目、またはサービス側の reCAPTCHA/Turnstile 等）
- [ ] 会社情報の確定（所在地・代表者・連絡先の公開範囲。現状は「お問い合わせ時にご案内」）
- [ ] プライバシーポリシー（フォームで個人情報を取得するため）と、必要に応じて特定商取引法に基づく表記の要否を確認
- [ ] イラスト素材（mco7-1〜6）のライセンス／生成元の記録を残す（ページ上のモチーフ説明は不要と判断し撤去済み）

### フェーズ2: 品質・SEO・パフォーマンス（目安 1〜2日）

- [ ] **Webフォントの最適化**: 現在は 18 ファミリを一括 `@import`。確定した **M PLUS Rounded 1c（＋必要ならフォールバック用 Noto Sans JP）だけに絞る**。`<link rel="preconnect">` と `display=swap` を `index.html` に移し、ウェイトも実使用分のみに限定
- [ ] 画像最適化: `public/images/mco7-*.webp` のサイズ確認、`width/height` 指定、`loading="lazy"`（ファーストビュー以外）、`srcset` の要否
- [ ] メタ情報: OGP（`og:title` / `og:description` / `og:image`）、Twitter Card、favicon、`theme-color`（浅葱グリーン系）
- [ ] `robots.txt` / `sitemap.xml`、canonical URL
- [ ] 構造化データ（Organization）の追加を検討
- [ ] アクセシビリティ監査: キーボード操作、フォーカス表示、見出し階層、`prefers-reduced-motion` 対応（Reveal / パララックス）、フォームのエラー通知
- [ ] Lighthouse（Performance / Accessibility / SEO / Best Practices）で目標値 **各 90 以上**

### フェーズ3: デプロイと運用（目安 0.5〜1日）

- [ ] ホスティング先の決定（Cloudflare Pages / Netlify / Vercel / レンタルサーバー等）
- [ ] 独自ドメイン（hannari.dev 系）と HTTPS、リダイレクト（www ↔ apex）
- [ ] CI: push 時に `npm ci && npm run build`（型チェック込み）を実行
- [ ] 公開後の動作確認チェックリスト（フォーム送信、各アンカー、スマホ表示、OGP プレビュー）
- [ ] アクセス解析の要否を決定（導入するなら Cookie を使わない軽量なもの。導入時はプライバシーポリシーに明記）

### フェーズ4: コンテンツ拡充（公開後・継続）

- [ ] Journal に実記事を追加（記事の管理方式を決める。下記「判断事項」）
- [ ] Works に実績・事例の追加（公開可能な範囲で）
- [ ] 会社情報の充実（所在地・沿革・代表挨拶など）
- [ ] 必要に応じて独立ページ化（記事詳細、プライバシーポリシー）

## 5. 判断事項（要決定）

| # | 論点 | 選択肢 | 推奨 |
| --- | --- | --- | --- |
| 1 | 未使用のテーマ29種・フォント19種の扱い | A. 残置（現状） / B. 削除して確定分のみに | **B**（CSS・フォント読込を軽量化。git 管理後なら復元可能）。フェーズ0で git 初期化後に実施 |
| 2 | フォーム送信先 | Formspree 等 / 自前 API / mailto のみ | Formspree 等＋mailto フォールバック |
| 3 | ホスティング | Cloudflare Pages / Netlify / Vercel / レンタルサーバー | 静的・無料枠・CI 連携の容易さで Cloudflare Pages もしくは Netlify |
| 4 | Journal の記事管理 | A. コンポーネント内の配列 / B. Markdown + ビルド時読込 / C. 外部 CMS | まず **A**（記事数が少ないうち）、10 本を超えたら B を検討 |
| 5 | 切替バーの復活可否 | 完全撤去 / 開発時のみ表示 | 開発時のみ表示（`import.meta.env.DEV`）は低コストで可能。必要になれば実施 |

## 6. リスクと対策

| リスク | 影響 | 対策 |
| --- | --- | --- |
| フォーム送信先未設定のまま公開 | 問い合わせを受け取れない | フェーズ1を公開のゲート条件にする |
| Google Fonts 依存（外部読込・全ファミリ一括） | 初回表示の遅延、外部障害時の字体変化 | フェーズ2で読込を絞る。システムフォントへのフォールバックは維持。必要なら自己ホスト化 |
| 個人情報の取り扱い（フォーム） | 法令・信頼性 | プライバシーポリシー整備、送信先サービスの保存場所・保持期間を確認 |
| イラストの権利 | 素材の権利関係が不明確になる | 素材のライセンス／生成元の記録を残す |
| git 未管理 | 変更の復元ができない | フェーズ0で最初に初期化 |

## 7. 完了の定義（Definition of Done）

- `npm run build` がエラー・警告なしで完了する
- フォームから実際に送信でき、受信を確認できている
- Lighthouse 各指標 90 以上（モバイル）
- デスクトップ／スマホで全セクションの表示崩れ・アンカーずれがない
- 公開 URL が HTTPS で到達でき、OGP が正しく表示される
- README の「確定デザイン」「フォーム設定」「デプロイ手順」が最新である
